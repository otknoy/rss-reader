# 設計方針

Go + HTMLテンプレート + PostgreSQL（部分更新が必要になったらHTMX）のモジュラーモノリスとする。
WebとRSS取得は同じイメージをDeploymentとCronJobで実行する。

## 境界のルール

1. モジュール間のimportは次の表だけを許可する。同じモジュール内は自由。
2. 非公開の実装は各モジュール配下の`internal/`に置く。Goコンパイラがアクセスを制限する。
3. テーブルは所有モジュールだけが操作する。モジュール別DBユーザーとスキーマへのGRANTで制限する。

| モジュール | 責務・所有データ | import可能な他モジュール |
| --- | --- | --- |
| feeds | 購読・取得状況 | なし |
| articles | 記事・本文・既読・お気に入り | なし |
| ingestion | RSS取得と登録の調整 | feeds、articles |
| search | 検索・将来の検索索引 | articles |

起動コードは`cmd/`に置き、各モジュールを接続する。
新しいモジュールや依存方向は、自動チェックの許可表を変更して追加する。
インターフェースや階層は必要になった時点で導入する。

## 自動チェック

`go test ./...`で依存方向を検査する。テストコードのimportも対象とする。
未知の内部パッケージへの依存も拒否する。検査対象は現在のビルド環境で有効なGoファイル。
`internal/`のアクセス制限はコンパイル時に検査される。
DB権限はComposeの統合テストで、他モジュールのテーブルへのアクセス拒否を確認する。

## 機能設計

- 購読解除後も取得した記事を保持する。
- 記事の重複はDBの一意制約で防ぎ、再取得で既読・お気に入りを上書きしない。
- 削除したRSS記事は削除日時を保持し、再取得で復活させない。
- 本文を保存し、検索索引はそこから再構築する。元サイトの全文取得は別途実装する。
- 最初は部分一致検索とし、日本語全文検索は導入時にPGroonga等を評価する。

将来のサービス分離はモジュール境界を単位に検討する。
分離時には通信・データ移行・障害対応の設計が別途必要になる。
