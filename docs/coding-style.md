# コーディング規約

改行、空行、インデントで、処理の順序と関連する要素のまとまりを示します。

## 共通

- 値を取得して直後に検証する場合は、取得と検証を続けて書きます。
  入力の検証からDB更新へ移るなど、処理の目的が切り替わる箇所には空行を1行入れます。
- 短くまとまった式は1行で書けます。
  長い式は、引数、条件、フィールドなど、読み手が個別に確認する単位で改行します。
- テストでは、準備・操作・検証の区切りを空行で示します。
  操作と直後のエラー確認は続けて書きます。

## GoとJavaScript

- Goは `gofmt` で整えます。
- 複数行の構造体リテラルやJavaScriptのオプションオブジェクトは、原則として1行に1フィールドを書きます。
- 長い条件式は論理演算子の後で改行します。
  条件の評価順や括弧によるグループを保ちます。
- JavaScriptの複数行の呼び出しでは、引数をインデントし、閉じ括弧を呼び出しの開始行と同じ深さに揃えます。

## HTMLテンプレートとCSS

- ブロック要素やテンプレートのループ・条件分岐は、入れ子に合わせてインデントします。
  長い開始タグは属性の境界で改行します。
- リンクやラベルの文言、空白を保持する要素、属性値の内部を整形するときは、表示される空白や生成される値を保ちます。
- CSSの短いルールは1行で書けます。
  宣言が複数あって見通しが悪くなる場合は、1行に1宣言を書きます。
  整形時はセレクターや宣言の順序を保ちます。

## SQL

- 長いSQLは句の境界で改行し、複数の条件や更新列はインデントします。
  列の並びと `Scan` の引数、プレースホルダー番号と渡す値の対応を保ちます。
- 適用済みのマイグレーションSQLは既存ファイルを保持します。
