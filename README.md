# 余白 / RSS Reader

個人用のRSSリーダーのプロトタイプです。Goのモジュラーモノリスとして実装しています。

## 起動

Docker EngineとDocker Compose v2があれば起動できます。ホストへのGoやPostgreSQLのインストールは不要です。

```sh
docker compose up --build -d
```

[http://localhost:8080](http://localhost:8080) を開いてください。
DB起動 → マイグレーション → Web起動の順に実行します。

1. 「購読を管理」でRSS / AtomのURLとフォルダーを指定し、「購読する」を押します。
2. 登録直後にそのフィードの記事を取得します。別の更新が実行中の場合は次回の自動更新で取得します。
3. 記事の詳細表示、既読切り替え、お気に入り、検索ができます。
4. 「購読を管理」→「記事URLを登録」からURL・タイトル・本文やメモを保存できます。

## 実装済みの機能

- RSS / Atomの購読登録・解除と一括取得、取得エラーの表示
- Webプロセス内の自動更新、RSSのTTL対応、条件付きHTTP取得
- 記事URLの手動登録
- 本文・画像のリッチ表示、元ページの本文抽出と保存・検索
- 未読・既読、お気に入りと絞り込み
- 日本語タイトル・保存本文の部分一致検索、20件ごとのページ送り
- 再取得時の重複防止と状態保持
- PostgreSQLへの永続保存、モジュール別DB権限

Web画面から記事を削除する機能はありません。購読フィードの解除後も記事は残ります。RSS記事・手動でURL登録した記事の本文を自動取得します。
記事を選択すると、左の購読フィード・中央の記事一覧を残し、右のカラムに本文を表示します。
記事を切り替えても一覧のスクロール位置と絞り込み条件を保持し、ブラウザーの戻る・進むにも対応します。
狭い画面では一覧と本文を切り替えて表示し、「閉じる」で一覧に戻れます。
元ページの本文はバックグラウンドで自動抽出・保存します。本文取得の手動ボタンはありません。
取得した全文も検索対象になります。RSSの本文・要約や既読・お気に入りは保持します。

詳細画面は段落・見出し・画像・リスト・引用・コード・表に対応します。
配信元のHTMLは許可した要素だけを表示し、スクリプト・フォーム・埋め込み・独自CSSを除去します。
画像は配信元から直接読み込みます。画像自体は保存しないため、配信元で削除された画像や
外部表示が制限された画像は表示できない場合があります。
JavaScriptで生成される本文、ログイン・購読が必要な記事などは全文を取得できない場合があります。
抽出が不十分な場合は元記事をご覧ください。
取得先は公開HTTP / HTTPS URLに限定し、ローカル・プライベートIPへの接続を拒否します。
初版の画面は標準フォームで動作し、HTMXによる部分更新は未導入です。
認証・全文検索・Kubernetesマニフェストはまだ実装していません。
ローカル利用向けにWebポートを127.0.0.1へ公開しています。

## 自動更新

Webと同じプロセス内でバックグラウンド取得します。追加のサービスやCronJobは不要です。
起動時に取得時刻を迎えたフィードを確認し、その処理の完了後、1分待って次の確認を行います。
新しく登録したフィードも次の確認で取得されます。

各フィードの取得後、次の間隔で次回取得時刻をDBへ保存します。

```text
更新間隔 = max(FETCH_INTERVAL, RSSのttl)
```

| 設定・フィード | 次回までの待機時間 |
| --- | --- |
| 通常設定（30分）、ttlなし | 30分 |
| 通常設定（30分）、ttl=10 | 30分 |
| 通常設定（30分）、ttl=60 | 60分 |

RSSのttlは分単位です。未指定、0、負数、整数以外、Goの時間表現を超える値は無視します。
Atom等でttlがない場合も通常の更新間隔を使います。
更新間隔は取得処理の完了時刻から計算するため、実際の取得は次回確認時以降になります。
再起動しても保存された次回時刻を引き継ぎ、期限前のフィードは取得しません。

`.env`で以下を変更できます。

```dotenv
AUTO_REFRESH=true
FETCH_INTERVAL=30m
```

`FETCH_INTERVAL`は`30m`、`1h`などの形式で、最小値は`1m`です。
`AUTO_REFRESH=false`でWeb内の定期実行を停止できます。
環境変数変更後は`docker compose up --build -d`を再実行してください。

- `reader fetch`は次回時刻を待たずに取得します。
- `ETag` / `Last-Modified`を送信し、304応答なら記事を再保存せず次回時刻を更新します。
- 取得失敗時は直前のttlとHTTP検証子を保持し、通常の間隔とttlの長い方を待って再試行します。
- 一つのフィードが失敗しても他は続行します。処理全体の上限は自動更新・CLIが10分、画面からの更新が2分です。
- PostgreSQLのアドバイザリロックで、手動・自動・CLIの同時取得を防ぎます。
  実行中の自動処理・CLIはスキップし、手動更新は409を返します。
- Web停止時はバックグラウンド取得もキャンセルし、終了を待ってDB接続を閉じます。

将来CronJobへ分離するときは、Webに`AUTO_REFRESH=false`を設定し、
同じイメージの`reader fetch --due`を定期実行します。
このコマンドは期限が来たフィードだけを取得して終了し、TTL・取得予定・ロックをそのまま共有します。
スケジュールの取りこぼしを減らすにはCronJobを1分間隔にします。大規模化時の並列化等は別途検討します。

## キーボードショートカット

| キー | 操作 |
| --- | --- |
| `j` / `k` | 次 / 前の記事を右ペインで開き、既読にする |
| `i` | 表示中の記事の元ページを別タブで開く |
| `f` | 選択した記事のお気に入りを登録 / 解除 |
| `Space` / `Shift + Space` | 開いている本文を下 / 上へスクロール |

一覧の端では、次 / 前のページの記事へ移動できます。
入力欄・IME変換中・購読管理画面の操作中はショートカットを無効にします。
Ctrl・Alt・Commandとの組み合わせも処理しません。

## 購読フォルダー

左サイドバーの「購読を管理」でフォルダーを作成・改名・削除できます。
フィード名をフォルダー名や「未分類」へドラッグして移動します。
フォルダー名を選ぶと所属フィードの記事に絞り込めます。未読・お気に入り・検索も併用できます。
フォルダーを削除すると所属フィードは「未分類」へ戻り、購読と記事は保持されます。

## OPMLのインポート・エクスポート

「購読を管理」の「OPML」から操作します。

- インポート：`.opml` / `.xml`ファイルを選択して「インポート」を押します。
  既存の購読に追加し、購読解除済みのURLは再購読します。既存記事や閲覧状態は保持します。
- 登録済みURL・ファイル内の重複は追加せず、不正なURLはスキップします。
  登録・重複・スキップの件数を表示します。
- エクスポート：「OPMLをエクスポート」から現在購読中のフィードを`subscriptions.opml`として保存します。
  保存したファイルは再インポートできます。購読解除済みのフィードは含めません。
- フォルダーも入出力します。入れ子は「技術 / Go」のように1階層にまとめます。既存フィードの分類は保持します。
- インポートは2MB・1000フィードまでです。XMLが壊れている場合は登録せず、DB更新も全件まとめて行います。
- 登録後のRSS・本文取得は既存の自動更新処理が行います。

## 記事本文の自動取得

RSS更新またはURLの手動登録で新しく保存された記事は、本文の取得待ちとしてDBに記録します。
既存記事も、本文がまだ取得できていないものをマイグレーションで取得待ちへ追加します。
削除済みの記事、取得済みの全文、既存の再試行予定は変更しません。
Webと同じプロセス内で、RSSの定期取得に続いて最大10件ずつ本文を抽出・保存します。
残りは次の確認で処理し、再起動しても取得待ちは失われません。
手動のRSS更新で新着が入った場合も、次の定期処理から本文を自動取得します。
記事を開くと取得済みの本文やRSSの要約をすぐに表示し、本文が未取得で取得可能な状態なら定期処理を待たずに取得を試みます。

- RSSが304（変更なし）でも、本文の取得待ち・再試行は処理します。
- 同じ記事を繰り返しRSSから取得しても、取得待ちは重複せず、保存済み本文も再取得しません。
- 失敗時はRSSの本文・保存済み全文を残し、30分後以降に再試行します。
- 記事単位のDBリースで別Podとの二重取得を防ぎます。
  取得処理が異常終了した場合、2分後に再度取得できる状態になります。
- 自動取得は1件45秒を上限とし、一つの失敗で他の記事を止めません。
- 開いている取得待ちの記事は状態を確認し、取得完了時に右カラムを更新します。
  記事一覧と本文のスクロール位置は保持します。
- 保存済みの全文は保持し、取得済み記事を毎回ダウンロードし直すことはありません。

`AUTO_REFRESH=false`では本文の定期取得も停止します。
将来CronJobから実行する`reader fetch --due`でも、同じ取得待ち処理を実行します。

## 開発

Compose Watch対応のDocker Composeでは、次のコマンドでソース変更時に再ビルドできます。

```sh
docker compose up --build --watch
```

`cmd/`、`internal/`、`go.mod`、`go.sum`を監視します。
マイグレーションを追加した場合は、通常の起動コマンドを再実行してください。
データは名前付きボリュームに残るため、コンテナを作り直しても保持されます。

```sh
# 次回時刻を待たずに手動でRSS取得
docker compose run --rm web fetch

# 期限が来たフィードだけを1回取得（将来のCronJob用）
docker compose run --rm web fetch --due

# ログ確認
docker compose logs --tail=100 web migrate

# 停止。DBのボリュームは保持する
docker compose stop
```

ポートや開発用パスワードは、必要に応じて初回起動前に`.env.example`を`.env`へコピーして変更します。
パスワードは接続URLへ埋め込むため、例のような英数字・ハイフン等のURLで安全な文字を使ってください。
DBユーザーとパスワードの初期設定は空のデータボリュームでのみ実行されます。
既存DBのパスワード変更は別途DB側の変更も必要です。付属のデフォルト値はローカル開発専用です。

## 検証

```sh
# Docker内で単体テスト・依存チェック・実DB統合テストを実行
docker compose --profile test run --build --rm test

# Go 1.27.4を利用できる場合の単体テスト・依存チェック
go test ./...
```

統合テストは専用の一時DBを作成し、終了時にそのDBだけを削除します。
通常の開発DBのデータは変更しません。
モジュール別DB権限、重複取得時の状態保持、購読解除後の検索、記事操作を検証します。
TTL・取得予定の永続化、DBロックの競合と解放、条件付き取得、定期処理の再試行・停止も検証します。

## 構成

- Go 1.27.4 / `net/http` / `html/template`
- PostgreSQL（Debian版）
- 実行用コンテナ：`gcr.io/distroless/static-debian13:nonroot`
- ビルド・テスト用コンテナ：Go公式Debianイメージ
- 実行コマンド：`web` / `fetch` / `migrate` / `healthcheck`

| モジュール | 責務 |
| --- | --- |
| `internal/feeds` | 購読・取得状況 |
| `internal/articles` | 記事・既読・お気に入り |
| `internal/ingestion` | RSS取得・解析と記事登録の調整 |
| `internal/search` | 検索、将来の全文検索への入口 |

依存ルールは [設計方針](docs/architecture.md) を参照してください。
DB接続情報は`FEEDS_DATABASE_URL`と`ARTICLES_DATABASE_URL`に分離しています。
マイグレーションだけが管理者の`DATABASE_URL`を使用します。
